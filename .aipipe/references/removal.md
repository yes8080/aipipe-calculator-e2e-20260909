# 从产品移除 aipipe

只移除当前项目引入的 aipipe 文件，不删除整个 `.github/` 或业务目录。

```text
.aipipe/
.github/workflows/aipipe-*.yml
.github/workflows/aipipe-*.yaml
```

1. 停止旧执行器，保存并推送需要交接的改动，核对未合并 PR 和开发分支。不因为卸载就删除未交付代码。
2. 当前工作流若已运行真实业务检查，先移交到项目自己的工作流。可以在迁移 PR 中改名并保留原检查名称，但避免两个工作流产生同名检查。检查名需要改变时，先使新检查成功，再切换 required checks，最后移除旧检查。只删除模板工具自测则无需移交它为业务测试。
3. 移出上述文件，清理工具中指向本仓库的入口。用户级通用转发 Skill 如仍服务其他项目可保留；它不会把已删除的规则自动找回来。
4. 调整 aipipe 专用的分支写入资格，确保 Owner 或后续维护身份能经正常 PR 维护；保留产品质量门禁。复用组织规则时不盲目删除它们。
5. 对不再使用的 App 安装撤销当前仓库选择，清理外部 token。共享 App 还服务其他仓库时，不直接删除整个 App 或它们使用的私钥。清理仅当前项目使用的标签和设置，保留 GitHub 交付记录。
6. 在临时干净检出中验证：移出后产品仍安装、构建、运行原生测试，产品代码和脚本不依赖 `.aipipe/`；需要持续 CI 时替代工作流实际通过，保护规则不等待已删除的检查。

业务 `docs/`、源码、测试、fixture、测试环境配置、锁文件、Maven / Gradle Wrapper 都是产品交付物，不能因为最初由 aipipe Agent 生成而一并删除。删除工作流不会自动保留 CI，也不会自动移除 required check 配置。

本机 CLI 独立于项目。仍使用其他 aipipe 项目时保留安装；全部停用后，按安装方式移除个人命令链接和专用 venv，或用 `pipx uninstall aipipe-workflow-cli`。不要把业务 Python 环境、共享 App 私钥或整个 `~/.config` 当成卸载范围。
