# 使用场景与选择规则

aipipe 提供 Skills、可生成的项目配置及其执行器。用户选择哪个 AI 工具、哪个模型、哪个会话执行每项工作；同一工具可以承担不同角色，但开发和独立验收须使用不同上下文及 GitHub 身份。

## 场景表

| 场景 | 需要做什么 | 不自动附加的工作 |
|---|---|---|
| 本地项目尚无 GitHub 仓库或暂时离线 | 可分析、设计、生成配置和运行本地命令；远端操作前再绑定仓库 | 不制造虚假 GitHub 记录 |
| 新项目，仅有想法或需求 | `plan` 设计文档；需要建仓库、命令和 App 时 `init` | 不因写方案就创建 App、发布 Issue |
| 新项目，已有完整方案 | `plan` 仅拆片，或直接 `publish` 已有计划 | 不重写已确定方案 |
| 传统项目，首次接入 aipipe | `init` 接入初始化，复用架构、文档、任务、分支、CI，生成配置；再处理当前任务 | 不生成新的开发方案，不重建历史任务或里程碑 |
| 已使用 aipipe 的项目，接手工作 | `resume` 核对现有配置、分支、PR 和交接；仅补失效项 | 不重复完整初始化 |
| 只做普通只读分析，尚未要求接入 | 直接分析现有代码与资料 | 不擅自安装或修改 GitHub |
| 只设计开发文档 | `plan` 的文档模式 | 不拆片、不发布 |
| 只编排里程碑和切片 | `plan` 的拆片模式，复用方案 | 不修改原方案或立即发布 |
| 只发布已有切片 | `publish` 预览、检查并按授权写 GitHub | 不重新设计，不启动客户端 |
| 已有明确 Issue 或缺陷任务 | `develop` 处理该任务；传统项目先做接入初始化 | 不强制批量规划其他任务 |
| 已有 PR，需要独立验收 | `review` 检查当前提交；需要正式接入的传统项目先补相关初始化 | 不要求重新开发或补写全项目方案 |
| 换机器、换工具 | `resume`，恢复本机 credential_ref 映射；复用 App/安装与远端记录 | 不复制私钥进仓库，不为每台机器注册新 App |
| token 过期、撤销或权限变更 | `init` 只处理身份缺口，再接续失败动作 | 不重发整批，不自动重试不确定的写请求 |
| 批量发布部分失败 | `publish` 核对已创建项，复用一致对象后续发缺项 | 不另起批次掩盖重复或冲突 |
| PR 返修、冲突、目标分支变化 | `resume` / `develop` 续原分支，重测并重新验收 | 不通过新 PR 清零返修次数 |
| 需求变更 | `plan` 仅修订受影响方案/未开工切片；已开工任务经明确决定调整 | 不让发布器覆盖已开发 Issue |
| 多模块或多个仓库 | 配置原生模块命令，各仓库独立绑定与交付，明确跨仓库依赖 | 不承诺跨仓库原子合并或内置并行调度 |
| 尚未建立业务 CI 的空项目 | 先做首个有效业务切片，合并前建立真实测试与审批门禁 | 不用模板工具测试换取业务绿灯 |
| 组织共享 App / 多项目复用 | 每仓库保留自己的安装与凭据引用，验证共享变更影响 | 不因一个项目停用而删除整个共享 App |
| GitHub Enterprise 或不支持所需规则的套餐 | 明确当前执行器仅支持 github.com；按实际能力补适配或保留只读/本地工作 | 不静默退回个人凭据或跳过质量门禁 |
| 升级 aipipe | 比对 `.aipipe/` 变更，保留 project.json、项目 plans 和定制约定，验证后更新 | 不覆盖业务文件与本机凭据 |
| 移出或停用 aipipe | 移交 CI/必需检查，清理工具文件和当前项目授权 | 不删业务 docs、测试、共享 App 或历史交付记录 |

## 接手已有项目的判断

只有 `.aipipe/` 目录不足以证明项目已接入，模板刚复制时也有该目录。应核对项目绑定、原生命令、用户本次需要的权限与真实 GitHub 记录。

传统项目的接入初始化是一项配置工作：识别项目 → 保存现有约定 → 生成配置 → 接入当前操作所需能力 → 验证已配置部分。其产出可包括原生命令清单、App 绑定及接入记录，不包含自动生成的新业务开发方案。

已有 aipipe 项目则核对已有事实并恢复，不把新机器缺一个 token 视为整个项目未初始化。初始化可以部分完成：本地配置就绪后能运行本地检查；缺少远端凭据只阻止依赖该凭据的操作，缺少有效门禁只阻止合并。

## 用户选择工具与模型

用户可以让 ZCode、OpenCode、Claude Code、Codex 或其他具备文件和命令能力的 AI 工具完成设计、拆片、发布、开发或验收。项目 `preferences` 只记录选择，执行器不解析它为启动命令，不连接模型 API，也不检查客户端是否存在。

持续开发使用宿主已有会话能力，用户手工启动和切换。Skills 决定本次行为，配置提供项目参数，执行器调用原生命令与 GitHub；任务进度继续以 GitHub 为准。
